## Lessons / follow-up
- **Slack MCP body-fetch gap** — persistent across all alert-channel bots that post block-format messages (Datadog, Watcher). This cycle is the 4th in a row (17:27Z, 19:08Z, now 20:11Z) where classifications fall back to ES time-correlation. If we add `slack_read_message_blocks` (if such an MCP method exists) or scrape Slack block JSON directly, monitor identity becomes confirmable. Until then, score caps at +4 from group+novelty signals alone, which is right at the DM threshold — small environmental shifts will flip-flop suppression. Worth a stability-review note.
- **Group-window heuristic at the boundary** — 1797s gap → grouped, 1801s → split. Two unrelated errors got bundled because they happened 30 min apart on the same channel from the same bot. The heuristic is doing its job (text fingerprint is the discriminator, but bodies are unfetchable). Possible refinement: when text-fingerprint is empty AND gap > 25 min, prefer split — minor stability-review item.
- **ES cluster memory pressure** — circuit-breaker trips on 1.9gb of in-flight aggregate data. Affected the broader aggregate-by-`@account_name` query I tried for G1. Lighter queries (smaller window, `_msearch` per-index) work fine. Worth a docs note in `playbooks/es-investigate.md` Step 3.5.
- **Sub-event B is a long-standing class** — per-tenant schema drift on legacy Classic Screens is a known support shape. Method's tailoring framework can paper over missing fields if Screen definitions guard against absence; consider whether Screen 1143's validator should `WHERE EXISTS` check before erroring. Filing-as-defect against Platform-Classic team is the right move.
