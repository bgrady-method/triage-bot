### Key findings
- One tenant (`camcraigconsulting`), one user flow. Someone is repeatedly editing the CustomAgenda and CustomEventSchedule tables in the designer. 12 failed SaveFieldLegacyExtended requests, 14:42–15:05Z.
- Root trigger: adding dropdown fields `CustomAgendaType` / `CustomAgendaStatus`. The dropdown child-table DDL fails because the key column type is invalid for an index. The rollback DROP COLUMN then fails because the column never existed. The parent table's spider metadata still references the column, so every later EditView regen fails with "Invalid column name". `CustomEventScheduleType` on CustomEventSchedule shows the same orphan shape. Its add-failure was outside this window or wasn't captured.
- Self-perpetuating per table: the user can't save any field change on CustomAgenda until the orphaned metadata is repaired. That makes this a real customer-facing blocker, not a ratio blip, even though it's one account.
- 24h baseline: tables-fields logs ~118 errors/day of chronic background classes. Today's burst is concentrated and different (view-regen cascade).

### Likely cause
Known cascade ki-2026-07-28, newly root-caused for this tenant. `AddDropDownFieldWithRollBack` fails to create the dropdown child table: the key column (`ColumnType.Text` with `dropdownField.Size` in stale origin/master 2026-07-06, FieldService.cs ~1240) is a type SQL Server rejects as an index key, consistent with nvarchar(max) or >900 bytes. The rollback is incomplete and leaves orphaned spider metadata, which then breaks every view regeneration on the parent table. Prod code is not verified (GH 403).
