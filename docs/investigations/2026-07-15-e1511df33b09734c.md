### Key findings
- **Real, low-volume error cluster traced to a single user session.** The 2 ES records in the window are, in order:

  2. `14:45:03Z` — Unhandled `System.Web.Mvc.HttpAntiForgeryException`: **"The required anti-forgery cookie '__RequestVerificationToken' is not present."**, StatusCode 500, path `POST /Initiate`, **Referer is the exact same OAuth callback URL** as record 1 (same `state`/`code` query params).
  - Both records share the same client IP (`74.77.205.226`), same browser (Chrome/Windows), confirming **one continuous user session**, not independent events.
  - A refined DD metric pull (5s resolution) shows 2 more error points at 14:46:50Z/14:47:30Z — consistent with the same user retrying the broken flow.
- **Mechanism hypothesis:** a user completed Microsoft SSO login, the OAuth callback's grant-code exchange failed ("invalid code" — possibly a double-submit or expired/reused code), and the immediate follow-up form POST to `/Initiate` failed separately because the anti-forgery cookie wasn't present — plausible if the cross-site OAuth redirect from `login.microsoftonline.com` back to `signup.method.me` isn't preserving the cookie (a `SameSite` cookie-policy candidate, not code-confirmed).
