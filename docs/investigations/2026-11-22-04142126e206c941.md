### Key findings
- **Root cause of this fire:** ReportGenerationAPI returns **HTTP 500** when the requested report has an empty layout (never saved in the Report Designer). It's a user-configuration condition, but it reports as a server error. One such request among ~1.5 req/min of Sunday traffic pushed the 10-minute error ratio over the Warn level.
- **It's the same account and screen every time.** This is the 4th fire from twinlocustbarnsinc `screenid688` (11-21 13:13Z `854e504e`, 11-21 17:54Z/17:57Z `6e2711fb`, 11-22 15:33Z). Earlier investigations recorded "fast 500 after spiderReports lookup, no ES/DD log". The ES Warning message linked by trace id now identifies the mechanism.
- It's distinct from the 13:45Z fire (`e707ff7f`: 30s spiderViewFields SQL timeout, cpvusanew) and from the innuwindow2 DevExpress/SQL-schema bug. The same monitor carries three distinct mechanisms.
- 175 "Report is Empty" hits in 7 days shows this is a common user-side condition. It only trips the monitor when volume is low.

### Likely cause
twinlocustbarnsinc has a button on classic screen 688 that generates a report whose definition was never saved. ReportGenerationAPI answers with a 500 ("The report is empty"), which counts as an error for monitor 316587947.
