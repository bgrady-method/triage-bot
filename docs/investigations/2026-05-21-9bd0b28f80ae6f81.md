## Lessons / follow-up
- **Trace-level drill-down**: when a monitor fires on a single p95 point, the natural next step is to pull the top-N slowest traces for that resource_name/window. The current `dd_search.py` does not expose APM trace search — adding a `traces` subcommand would let the bot find the offending tenant/action automatically.
- **Monitor tuning**: if these single-point spikes are noise, consider switching monitor 117279738 from a single-evaluation threshold to a 3-of-N rule, or raising threshold from 3 s to 4 s. Current single-spike sensitivity correlates strongly with operator paging fatigue.
- **Group-window**: see Group C investigation — this and Group C are 30 min apart and arguably the same root cause. Consider extending `group_window_minutes` to 60 for `alert-runtime-monitoring`.
