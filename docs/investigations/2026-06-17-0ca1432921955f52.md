### Key findings
- **Root cause (confirmed by stack + source):** `TimeZoneLookup.GetSystemTimeZoneById(tzID)` maps friendly names (EASTERN/CENTRAL/PACIFIC) to Windows tz ids, but the **`default` case calls `TimeZoneInfo.FindSystemTimeZoneById(tzID)` directly**. On the Windows classic hosts an IANA id like `America/New_York` is not a valid Windows tz id, so it **throws `System.TimeZoneNotFoundException`**.
- **Why it spams the log:** every caller (`GetUtcOffset`, `IsDaylightSavingTime`, etc., lines ~189-312) is written to the contract `var tz = GetSystemTimeZoneById(tzId); if (tz == null) return -1;` — they expect **null** on an unknown id, not an exception. The throw is therefore unhandled → logged each call.
- **Account-data driven:** 95% of volume is one account (`thestoragegroup`) whose stored timezone is the IANA string `America/New_York`. supplyshield (18) is the same shape. The bug is latent in the code but only fires for accounts whose stored tz is an IANA id.
- **Onset:** fresh burst today (0 at 13:00Z → 396 by 19:08Z). Historically intermittent (06-03, 06-10) but masked by the ES 401 outage — so this is "newly visible," not necessarily brand-new.
- **Scope:** Classic stack only (PROD-CLASSIC-01/02). Independent of the modern-gateway ki-21 XHR burst and the runtime-core ki-24 RTC latency that fired in Slack this cycle — same wall-clock window, different stack; no causal link found.

### Likely cause
A latent defect in the Classic shared timezone utility (`GetSystemTimeZoneById` throws instead of returning null / normalizing IANA ids), triggered by account(s) whose stored timezone is an IANA id (`America/New_York`) rather than a Windows id (`Eastern Standard Time`) or the friendly form the switch already handles. ~396 unhandled exceptions/hr across both classic nodes, 95% from `thestoragegroup`.

## Proposed fix (single file, ~18 lines) — legacy-common-core `TimeZoneLookup.cs`
```diff
                 default:
-                    return TimeZoneInfo.FindSystemTimeZoneById(tzID);
-
+                    try
+                    {
+                        return TimeZoneInfo.FindSystemTimeZoneById(tzID);
+                    }
+                    catch (TimeZoneNotFoundException)
+                    {
+                        // Callers expect null on an unknown id (see GetUtcOffset / IsDaylightSavingTime
+                        // callers: 'if (tz == null) return -1'), NOT an unhandled exception. IANA ids such
+                        // as "America/New_York" are not valid Windows tz ids and were throwing ~396x/hr
+                        // (95% account=thestoragegroup) on PROD-CLASSIC-01/02. Best-effort map the common
+                        // North-American IANA ids to Windows ids; otherwise honour the null contract.
+                        switch (tzID)
+                        {
+                            case "America/New_York":    return TimeZoneInfo.FindSystemTimeZoneById("Eastern Standard Time");
+                            case "America/Chicago":     return TimeZoneInfo.FindSystemTimeZoneById("Central Standard Time");
+                            case "America/Denver":      return TimeZoneInfo.FindSystemTimeZoneById("Mountain Standard Time");
+                            case "America/Los_Angeles": return TimeZoneInfo.FindSystemTimeZoneById("Pacific Standard Time");
+                            default:                    return null;
+                        }
+                    }
```
