### Key findings
- Single account (`ciamedical`), single endpoint (`ExportController.ExecuteExportAsync`, `ExportController.cs:55`), two back-to-back retry bursts ~30s apart — consistent with a user retrying a failed export in the UI.
- Root SQL error is thrown from a dynamically-built `CREATE VIEW` statement (`viewTempExport81251371744948728c50ecd5d06bd8d7`) whose generated `WHERE` clause ends in a stray semicolon before the closing paren (`...AND Quantity >'0';)`) — a malformed-SQL-generation bug in the export filter builder, not a data-layer/DB availability issue.
- Filter values involved: item-list export filtered on `ItemNPManufacturerName` (Baxter/ICU/B Braun/Metrix/CIA) and `ItemNPDescription` (bag, excluding sodium/saline/water/solution) — a fairly elaborate multi-clause filter, suggesting the semicolon-insertion bug is triggered by some property of this specific filter combination (number of clauses, or a specific value) rather than being universal to all exports.
- Self-recovered: `overall_state` was `OK` by scan time; no repeat since the two bursts.
- Not extrapolated beyond this account — single account, single endpoint, no shared-infrastructure signature (see Extrapolation findings below).

### Likely cause
The Import API's dynamic SQL view-builder for `ExecuteExportAsync` produces malformed SQL (trailing `;` before the closing paren of the `WHERE` clause) for this account's specific multi-clause item-list filter, causing every export attempt with this filter to fail with a SQL syntax error. Bug-type guess: **code** (dynamic SQL construction defect in the export filter builder), not a data or environment issue.
