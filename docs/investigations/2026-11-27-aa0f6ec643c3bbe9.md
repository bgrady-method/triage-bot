### Key findings
- 100% of Treeform's errors came from one browser session, and nearly all were status 0 "Failed to load" or console "Network Error". The browser never received an HTTP response.
- The failing endpoints were unrelated to each other (preferences/v3 GetReleaseFeatureFlag ×2 flags, apps/manage LegacyPermissions, account/learning/progress, preferences/v3/external/Account). That fits the whole client link dropping, not one backend failing.
- The burst lasted about 3m20s, which looks like a cellular/hotspot dropout (T-Mobile ISP egress on a desktop Mac). The app's pollers kept firing XHRs during the outage, and the count crossed the 25/40 thresholds.
- There were 0 server-side errors for the account, 0 gateway errors, and 0 events 24h earlier.

### Likely cause
One real Treeform user lost connectivity for about 3 minutes, and the account-scoped XHR monitor counted the client-side aborts. Method was not down. This is the same family as `fa-2026-11-25-perfectlypurepools3-single-session-cellular-network-drop-xhr-noise` and the 11-20 to 11-25 siblings.
