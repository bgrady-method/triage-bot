## Lessons / follow-up
- **KB match quality:** `ki-runtime-core-target-group-port-mismatch` has `match.any_of: [{contains:"prod-rt-04"}]`, which matches *any* alert naming prod-rt-04 even though that entry is a resolved, specific 404 issue. This produced a spurious match here. Narrow that term (e.g. require "target group" / "port 5000" / "404") so it doesn't shadow genuine host events.
- **Centreon ↔ ES host mapping gap:** the bot cannot map Centreon's `prod-rt-04` label to an ES MachineName / EC2 IP. A small lookup table (Centreon host → IP/MachineName) would let future cycles confirm the hung host and quantify its tenants.
- Operator engagement (ops already rebooting) correctly applied −3 to the score; the DM still fired (score 6) because it's a critical-path runtime host with a 33-alert cascade — Ben should know even when ops is on it.
