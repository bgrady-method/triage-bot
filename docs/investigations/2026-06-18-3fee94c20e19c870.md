### Key findings
- The inbound Rainforest **webhook events** endpoint `POST /api/v1/payments/rainforest/events` (runtime-core-api) throws an **unhandled** exception → HTTP 500.
- Full stack (index `method-runtime-api-2026.06`, host ip-172-31-206-255, trace `6a34153b00000000cf38bcb499af81c2`):
  ```
  Runtime.Core.Exceptions.AccountNotActiveException
    at Runtime.Core.Engine.Account.AccountContext.GetAccountDetailsAsync(...) AccountContext.cs:line 557
    at Runtime.Core.Engine.Account.AccountContext.InitAsync(Int32 accountId, ...) AccountContext.cs:line 106
    at Runtime.Core.Engine.Actions.ActionContext.InitAsync(...)
  ```
- **Mechanism (confirmed in code, `Runtime.Core.Api/Controllers/PaymentsController.Rainforest.cs`, `ProcessRainforestWebhookAsync`):** the webhook is first persisted (`_webhookMessageService.SaveAsync`, line ~38, in its own try/catch). Then `_context.InitAsync(accountId.Value, …)` runs inside a try whose catch block does `_logger.LogError(...); throw;` (line ~59-63). When the webhook's account is **inactive**, `InitAsync` raises `AccountNotActiveException`, the catch re-throws, and the request returns **500**.
- Rainforest delivers webhooks via Svix, which **retries on 5xx** → the same inactive-account webhook is redelivered repeatedly, producing the recurring low-volume 5xx bursts the monitor caught.
- Low volume (payments are low-QPS) but **customer payment flow + P2** — higher priority than the two chronic latency recurrences this cycle.

### Likely cause
A non-retryable condition (account inactive) is handled as a retryable server error. The webhook receiver lacks a `catch (AccountNotActiveException)` (and likely other permanent-failure) branch that acks with 2xx, so Svix retry-storms a webhook that can never succeed.

### Proposed fix (single-file, ≤30 lines — see KB fix_template)
```diff
             await _paymentService.SendRainforestWebhookSlackNotificationAsync(rainforestWebhookMessage, _context);
                 return Ok();
             }
+            catch (AccountNotActiveException ex)
+            {
+                // Account inactive — retrying will never succeed. Webhook already persisted above; ack to stop Svix retries.
```
