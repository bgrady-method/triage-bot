- Real, reproducible bug: `GenerateReport` throws `ArgumentNullException` inside DevExpress's report-layout deserializer when `typeName` is null — almost certainly a stored report layout (DevExpress `.repx`/XML) missing or containing a corrupted/unregistered control-type attribute for the specific report being generated.
- Not account-specific in aggregate: the 7-day sweep shows the same signature recurring across at least 5 unrelated customer accounts, each in its own isolated burst — points to a systemic issue in report-layout handling (e.g., an old/deprecated report template, a migration gap, or a shared report definition), not five independent per-tenant data problems.

## Likely cause
A recurring `System.ArgumentNullException` in `ReportGenerationService.ReportGeneration.GenerateReport` → DevExpress `XtraReportsSerializationContext.DeserializeObject`, triggered when a stored report layout references a `typeName` that resolves to null — consistent with a corrupted, missing, or version-mismatched report template. Root cause of *why* `typeName` is null (which specific report/control, when introduced) not yet determined — needs someone with DevExpress-report-layout access to inspect one of the failing report definitions (start with `ucpinc`, `mokanfastenerandsupply`).
