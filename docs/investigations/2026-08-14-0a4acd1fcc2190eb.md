See those groups' investigation docs for the cross-reference.

### Likely cause
For approximately 70 seconds (2026-08-14T14:09:00Z–14:10:10Z), calls from `runtime-core-api` (and other internal callers) through `microservices.method.int` to multiple, unrelated backend virtual apps (`ms-preferences-api`'s `featureflags` endpoint, `ms-tags-api`, `ms-scheduler-api`, `authservice`) stalled with no response until the caller's 100-second `HttpClient` timeout fired. Because the named backend (`ms-preferences-api`) was independently confirmed healthy on its own metrics throughout, and the stalled calls spanned multiple, otherwise-unrelated virtual apps, the fault most likely sits in the shared network/reverse-proxy hop to `microservices.method.int` itself (nginx worker stall, IIS site-level hiccup, or a transient network partition) rather than in any single backend service's code. The event was brief and fully self-recovered; exact trigger not independently confirmable from available telemetry (methodcrm-org `GH_TOKEN` 403 gap blocked repo/deploy checks on the implicated repos).
