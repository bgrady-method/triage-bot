### Key findings
- **Single dominant root cause identified:** `TypeError: Cannot read properties of undefined (reading 'ControlId')` thrown inside `isUsingControl()` in `actioneditor.for-legacy.min.js`. The error trips on every Angular `$digest` cycle while the user is on the action-editor "versions" page, generating dozens of errors per session and 43+ in DD in the 1h window.
- **Multi-account, not user-specific:** the same bug hits `prestonhardware` at 14:08:39 (F1, designer URL) and `ramexteriorsinc` at 14:49:13+ (F2, routines/versions URL). Bug is in shared legacy MethodUI code path that triggers on a specific App/Routine/Control configuration shape.
- **Affected code path:** `isUsingControl` function in the legacy action-editor module. The function is called from within an Angular `$digest` propagation, so it re-fires every digest cycle until the page is unloaded — explains the high error count per user.
- **Suspected source location:** `method-platform-ui` repo, `MethodUI/` legacy half, file matching `actioneditor.for-legacy.{ts,js}` or `ActionEditor` folder. The minified source map points to line 2:3089359 which decodes through the m-one webpack output.
- **Fix shape:** classic JS null-check defect. The function dereferences `.ControlId` on a value that's `undefined`. Fix is to either (a) return-early-if-falsy at the top of `isUsingControl`, or (b) protect the specific dereference with `?.` / `if (control)`. Confidence on fix shape: 0.85. Confidence on producing a minified-aware diff: 0.3 (we'd need to edit source, then rebuild).
- **No deploy correlation:** m-one frontend last deployed 2026-05-06 (15d stale). The bug existed before today; surfaced now because users navigated to the trigger path.

### Likely cause
The `isUsingControl()` helper in the legacy action-editor receives a control reference that's `undefined` under certain App/Routine/Control combinations (likely a deleted control or a control whose definition didn't load fully) and crashes on `.ControlId`. Because the call site is inside an Angular `$digest`, the error re-fires every cycle, flooding RUM and tripping the per-account XHR-error monitor (>40 errors / 5 min). The bug is in shipped legacy code that pre-dates the 2026-05-06 last deploy.
