### Key findings
- The two monitors' `last_triggered_ts` (13:36:39Z / 13:38:31Z) lag ~12-16 minutes behind the actual p95 spike (13:20:00-13:24:40Z, peak 3.79s) because both use rolling 5-10 min average windows.

### Likely cause
A transient Redis connectivity blip (~13:20-13:26Z) opened a client-side circuit breaker on ms-tables-fields-api, forcing cache-fallback reads that drove p95 request latency to 3.79s (vs 1.0s/0.25s monitor thresholds); self-recovered within ~5 minutes. The same Redis instability plausibly also drove the runtime-core-api RTC p95 spike investigated separately this cycle. No Method code defect identified.
