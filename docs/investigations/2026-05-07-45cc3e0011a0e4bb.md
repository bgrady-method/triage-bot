### Key findings
- DD Watchdog APM/infra monitor (236570583) last_triggered timestamp matches the Slack alert exactly (11:48:33 vs 11:48:34 UTC), confirming this monitor is the alert source
- `GET /gateway/syncutil/syncwidget/<account>/GetSyncWidgetInfoAsync` is failing with HTTP status:0 (network-level failure — no HTTP response) for 13+ distinct customer accounts across Invoice, Estimate, and SalesOrder views
- Status:0 indicates the gateway cannot reach the sync-util backend at all (connection refused, timeout, or CORS preflight failure)
- `ms-sync-util` has no Datadog APM instrumentation — server-side error details are entirely invisible
- No recent deploys to ms-sync-util or any of the four baseline repos in the ±4h alert window
- Backend prod error rate (all services) is low/steady; no signs of a cascading failure in other services
- Watchdog monitor is now OK — the Watchdog story either resolved or fell out of its 30-min query window

### Likely cause
The `ms-sync-util` service or its IIS app pool has stopped responding. The Ocelot gateway (`ms-gateway-api`) is unable to proxy requests to `/syncutil/`, causing the browser to receive a network-level failure (status:0) rather than an HTTP error code. Since there are no recent deploys and no other backend degradation, this is most likely an IIS pool crash/hang or the service process exiting unexpectedly. A QBO OAuth token failure causing the service to hang on startup is also possible given the sync-widget is QuickBooks-integration-facing.

## Lessons / follow-up
1. `ms-sync-util` has no DD APM instrumentation — this makes triage very difficult. Request the team add Datadog .NET APM tracing to ms-sync-util (see ms-sync-util CLAUDE.md requirements).
2. The Watchdog monitor (236570583) fires for ANY APM or infra anomaly in prod, making the alert text and affected service opaque. Consider creating a service-specific Watchdog monitor for `ms-sync-util` or adding a synthetic monitor hitting the GetSyncWidgetInfoAsync endpoint.
3. ES/Kibana continues to be unavailable (403) — this blocks log investigation for all non-DD-APM services. Escalate or fix the allowlist.
4. The sync widget status:0 failure pattern (many accounts, same endpoint, no deploy) is consistent with a process crash or pool hang. This warrants an IIS health check monitor for the ms-sync-util pool.
