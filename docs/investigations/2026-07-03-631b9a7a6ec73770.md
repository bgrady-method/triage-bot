### Likely cause
`SeriesDataProvider.GetSeriesIdAsync` (Scheduler.Core, `ms-scheduler-api`) is called with `recordId = -1` for account `lafittesseafood`, which appears to be a sentinel/unset value from the caller rather than a real record ID. Root cause is most likely upstream — something in this account's Activities data (or the client calling the API) is passing `-1` when it should either omit the call or pass a valid record ID.
