### Key findings
- **Bytes burst (what fired the monitor):** ~16 GB moved through prod-web-alb between 14:10 and 14:50Z, roughly 5-15x the hourly baseline. Request count stayed flat, so this was a handful of very large transfers (downloads or uploads), not a request flood. Avg target response time peaked at 14.3s at 14:30Z, consistent with long-running large transfers. The burst ended by ~14:55Z. The 1h rolling monitor should clear on its own by ~15:50Z.

Target-side 5xx stayed ~0, so the LB itself was refusing or failing requests. Its timing (before the bytes burst) and AZ profile (1a only) don't match the bytes burst, so it is probably a different mechanism. No in-scope monitor fired on it.

### Likely cause
The bytes burst was a heavy client pulling or pushing large payloads through the integration plane; the domain and client can't be determined without the S3 access logs. The ELB-5xx storm is unexplained (possibly LB capacity, a TLS/handshake issue, or an AZ-1a node problem).
