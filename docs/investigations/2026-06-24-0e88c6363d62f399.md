### Key findings
- Deploy-regression: today's release makes QBDT sales tax calculate to **0** on Save. Confirmed by Jira ("today's release") and the swat thread (Connect team reverting).
- **Silent failure mode** — returns HTTP 200 with the wrong value, so no APM error-rate, latency, or 5XX monitor fires. This is why Datadog/ES show nothing diagnostic; the only signal is customer support tickets + swat. This is a monitoring blind spot for value-correctness regressions.
- Breadth: ≥4 named accounts, "all big accounts have reported," I1 impact, all users per account affected. Lower bound on impact is well into the hundreds of users (excelpoolservice alone = 20 licenses; "big accounts").
- No matching KB entry (closest, `ki-2026-04-17-quickbooks-xero-servertime-race-sync-skip`, is a *sync-skip* race — different mechanism; resolved).

### Likely cause
A code change in today's release altered the QBDT sales-tax calculation on transaction Save such that the computed tax is zeroed before persistence. Owned by the **Connect** team (Accounting Sync / QBDT). Mitigation already underway: revert of today's release.
