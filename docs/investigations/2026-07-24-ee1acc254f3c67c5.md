- **This occurrence differs from the prior two**: both 2026-06-14 and 2026-07-07 were single-account/single-session (one client retrying a malformed call). This occurrence spans 3 distinct accounts/emails simultaneously — broadening beyond the documented single-session shape, though the underlying defect (unhandled empty-accountName path) is identical.
- 0 recent deploy correlation beyond the `dd_version` tag on the failing spans (2026-07-22 13:38, ~2 days prior — not a same-cycle regression).

### Likely cause
Same confirmed defect as the prior 2 occurrences: `SecurityController.ExpireSessionTokenAsync` does not validate/short-circuit on an empty `accountName` before calling `AccountContext.InitAsync`, which throws an unhandled `AccountNotFoundExceptions` (surfaced as HTTP 500). Root cause of *why* 3 separate clients hit this in the same ~30s window this time (vs. one client on prior occurrences) is not established — could be a shared front-end code path issue (e.g. a stale-JWT edge case triggered by a recent client release) rather than 3 independent unrelated incidents, but that's speculative without client-side telemetry this bot doesn't have access to.
