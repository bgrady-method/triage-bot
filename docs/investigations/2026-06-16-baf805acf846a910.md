### Likely cause
Method's short-link (MIURL) domain was switched off `miurl.cc` to an alternate domain that is not resolving/serving, so customer-facing short links (e.g. free-hour emails) return the browser "site can't be reached" page. The fix in motion is to revert the short-link domain back to `miurl.cc`. This is a DNS/domain-configuration regression in the URL-redirection layer, not a code defect in legacy-miurl-api.
